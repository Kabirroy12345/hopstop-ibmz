HopStop: stop mule payments at the first hop

Track: Real-Time AI for Critical Decisions  |  Transaction-time money-mule scoring on IBM LinuxONE with Snap ML and the Telum Integrated Accelerator for AI
Kabir Roy, B.Tech CSE, VIT Bhopal  |  IBM Z Datathon 4 (17-18 Oct 2026)  |  Data: IBM Transactions for AML (synthetic, CDLA-Sharing-1.0)

Problem

Mule accounts pass cyber-fraud money onward within minutes, while AML transaction monitoring often runs hours later. Each extra hop spreads the money across more accounts and banks, which makes freezing and recovery harder. HopStop moves the mule check into the payment path: score each outgoing transfer before it settles, and pause it while the money is still close to the victim.

Architecture

IBM LinuxONE instance (s390x) - data, features, model and decision stay on one platform
1. Payment streamIBM AML HI-Small replayed in timestamp order at set rates (Python producer; Kafka if available)
→
2. Feature engineIn-memory per-account state: fan-in/fan-out over 1h/24h, pass-through ratio, time since last credit, new-counterparty flag, amount z-score. Past events only.
→
3. ScoringLightGBM/XGBoost model imported into IBM Snap ML (AI Toolkit for IBM Z container). tree_format=auto: Integrated Accelerator for AI if present, else CPU.
→
4. Policy layerThresholds set by alert budget: allow / step-up / hold. Top-3 reason codes from per-feature contributions.
→
5. Analyst viewLive queue of held payments, reason codes, account hop graph, latency panel (p50/p99, CPU vs accelerator).
Offline path: training and threshold tuning on a time-based split (early days train, later days test). The same feature code runs offline and online to avoid train/serve skew.

Why IBM Z, concretely

  • Co-location: where core payments already run on Z, scoring on the same platform avoids shipping transaction data to an external AI server and removes a network hop from the decision.
  • On-chip inference: Telum (z16) and Telum II (z17) include an on-chip AI accelerator; Snap ML can map tree ensembles to it. We report measured latency, accelerator vs CPU-only.
  • Data protection: stored data and logs encrypted with AES-GCM via OpenSSL (CPACF-accelerated on Z). Stretch: run the scorer in an IBM Secure Execution guest if the event environment supports it.

Demo storyline (3-minute video)

  1. A fan-out laundering chain from the patterns file starts replaying in the stream.
  2. Hop 1 transfer is scored on LinuxONE; HopStop returns HOLD with reason codes (e.g., high pass-through ratio, burst of new counterparties).
  3. Analyst queue shows the held payment and the account hop graph; downstream hops never receive the funds.
  4. Latency panel: p50/p99 for CPU-only vs accelerator; recall vs rules baseline at the same alert rate.
